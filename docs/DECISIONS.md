## D-11. 퇴직소득세 계산 로직 우선 구현, 홈택스 대조는 별도 진행

  공식을 손계산한 값으로 먼저 구현·테스트하고, 홈택스 실측 대조는 운영자가 별도로 진행

  반올림 vs 절사 등 단수처리 가정(lib/calculators/severance-tax.ts 주석 참고)이
  틀릴 가능성 있음
- 결과(07-27): 운영자가 홈택스 "2024년 귀속 퇴직소득 지급명세서 모의계산"으로 SPEC 3케이스

  `calculateServiceYears`가 "입사일로부터 정확히 N년째 되는 날" 퇴사를 N년으로 처리하던
  것을 N+1년으로 정정(홈택스 공식 예제표로 확인), (2) 실수령액 계산 시 세금을 10원 단위로
  절사하는 로직 추가(홈택스 "차감원천징수세액" 방식). 수정 후 3케이스 전부 오차 0원 확인.
  §4(도구 2) 착수 가능. 검증 범위는 SPEC 3케이스가 실제로 거친 구간(근속연수공제 4개 구간 중
  3개, 환산급여공제 5개 구간 중 1개, 기본세율 8개 구간 중 1개)에 한정되며, 대조에 사용한
  시뮬레이터는 "2024년 귀속" 기준이라 2026년 세법과 완전히 동일하다는 보장은 아니다(다만
  소득세법 §55 기본세율은 2021년 개정 이후 변동 없음).

## D-12. DB/DC 전환 계산기: 과거 근속분(이미 근무한 기간) 미반영, 미래 적립분만 비교
- 결정일: 2026-07-28 / 상태: 확정 (한계로 기록, 재검토 여부는 보류)
- 배경: 최종 브랜치 리뷰에서 `/tools/db-dc` 페이지 문구가 "과거 근속분에 대한 DB 권리는
  전환 여부와 무관하게 그대로 유지된다"고 설명하고 있었으나, 이는 사실과 다름 — 실제 DB→DC
  전환 시 과거 근속분도 전환 시점의 임금 수준으로 함께 정산(크리스탈라이즈)된다. 임금피크제
  적용 후에 전환하면 과거 근속분까지 낮아진 임금 기준으로 정산되어 불리해지는 것이 실제
  현장에서 조기 전환을 서두르는 흔한 이유 중 하나임. 페이지 문구는 정정했으나(위 리뷰 반영
  커밋 참고), 계산 로직 자체가 과거 근속연수를 입력받지 않고 미래 적립분만 비교하는
  단순화는 그대로 유지되는 실제 한계임
- 결정: `/tools/db-dc`의 비교 범위는 계속해서 "지금 시점부터 정년까지 새로 쌓이는 퇴직급여"로
  한정한다. "이미 근무한 근속연수" 입력 필드는 추가하지 않는다 — 계산 단순성과 UX를
  우선한다
- 트레이드오프: 입력 필드 하나를 늘리지 않는 대신, 근속연수가 긴 사용자일수록 실제 유불리
  판단에 필요한 전체 그림(과거 근속분 정산액 포함)을 이 도구가 보여주지 못한다. 리뷰어
  추정으로는 이 단순화가 손익분기 수익률 자체에 주는 편향은 대체로 작고(약 0.1~0.5%p,
  보수적 방향 — 이 도구가 DC 전환에 필요한 수익률을 실제보다 다소 높게 보여주는 경향) 방향은
  안전한 쪽이지만, 화면에 표시되는 절대 금액은 과거 근속분을 포함한 실제 비교보다 상당히
  작게 나타날 수 있음
- 미결 사항: 제대로 다루려면 "이미 근무한 근속연수" 입력을 추가하고 DB/DC 공식을 과거
  근속분까지 포함하도록 확장해야 함 — SPEC.md §4 개정 후보로만 남겨두고, 이번 브랜치에서는
  착수하지 않음

## D-13. 2주차 가이드 보강: G3 주제를 예비 후보로 교체, 가이드 14편 체제 전환
- 결정일: 2026-08-13 / 상태: 완료
- 배경: TASK_guide-week2.md의 T0(기존 가이드 인벤토리·주제 중복 검사) 수행 중, G3 원안
  "퇴직금 중간정산 후 근속연수 합산 규칙"이 기존 가이드 #7(severance-interim-settlement,
  "퇴직금 중간정산 조건과 세금")과 "중간정산을 받으면 근속연수가 리셋된다"는 핵심 결론을
  이미 공유하고 있음을 발견. 원안대로 진행하면 사실상 동일 결론을 재서술하는 중복 콘텐츠가
  될 위험
- 선택지: (A) 원안 유지, 심화 시나리오(2회 이상 중간정산·재입사 합산 등)로 좁혀 차별화 (B)
  지시서에 명시된 예비 후보 중 하나로 교체
- 결정: B — "55세 이후 연금 수령 시 건강보험료 영향"으로 교체 (운영자 확인 후 진행).
  T0 규칙("겹치면 즉시 다른 후보로 교체")을 그대로 적용
- 근거: 애드센스 재신청의 핵심 진단이 "가치가 별로 없는 콘텐츠"였던 만큼, 기존 글과
  결론이 겹치는 신규 페이지를 늘리는 것은 오히려 역효과. 건강보험료 영향은 완전히 새로운
  주제라 중복 위험이 없고, 계산기 의존 없이 개념 설명만으로 작성 가능해 리스크도 낮음
- 트레이드오프: 원안은 기존 계산 함수(`calculateServiceYears`/`calculateSeveranceTax`)를
  재사용해 계산 예시를 넣기 쉬웠던 반면, 교체안은 계산 예시가 없는 개념형 콘텐츠가 됨.
  또한 건강보험료 관련 구체적 기준액(피부양자 소득 기준 등)은 매년 고시로 바뀌어 본문에
  싣지 않고 "국민건강보험공단 확인 필요"로 서술함 — 정확성 리스크를 낮추는 대신 콘텐츠의
  구체성은 다소 낮아짐
- 결과: 신규 가이드 4편(IRP 연금수령한도 계산법, 임금피크제 앞두고 DB→DC 전환 시점, 55세
  이후 연금 수령 시 건강보험료 영향, 55세 이전 퇴직금 수령 시 세금 불이익) 작성 완료로
  기존 10편 + 신규 4편 = **가이드 14편 체제로 전환**. IRP 연금수령한도 계산을 위해
